# Virtual Camera v0.1.0 — Developer/reference source release

Released 2026-10-24. This release consolidates the virtual-camera feature work,
Android 13 integration, Raspberry Pi 5 / Android 17 port, qualification reports
and reviewed tutorial into `main`.

## Included

- Integrated producer broker and platform-owned BufferQueue/JNI relay feeding a
  vendor camera HAL through stable AIDL V6.
- Up to four producer slots with descriptor-derived capabilities, stream/FPS
  negotiation, token-bound readiness and registration/configuration/connection
  lifecycle guards.
- Acquire/read/destination fence handling, fresh-submission admission and
  failure reporting instead of synthetic successful frames when sources stall.
- RGBA GPU composition, GPU-assisted YUV conversion with CPU plane copies, and
  CPU JPEG output. These paths have different performance characteristics.
- Vendor APEX packaging and target-specific integration/build helpers; matched
  base framework/JNI, policy, VINTF and signing trust remain prerequisites.
- Pi split demo with real Camera2 output, SurfaceView/TextureView preview
  selection, VGA/1080p and 30/60/120-fps target controls, interactive source-color
  changes and compositor-based freeze/resume.
- Default-off profiling experiments, detailed performance evidence, pixel
  identity checks, host regression tools and updated nine-lesson tutorial.

## Validation for this release

The merged candidate passed all five host scripts:

```sh
bash scripts/test-fence-safety-host.sh
bash scripts/test-frame-identity-host.sh
bash scripts/test-lifecycle-slot-host.sh
bash scripts/test-producer-capabilities-host.sh
bash scripts/test-renderer-mailbox-host.sh
python3 -m unittest discover -s tests -p 'test_*.py'
```

Python discovery passed **48 tests**. Host tests cover fence decision/ownership
faults, real-fd failure cases, pixel-marker decoding, slot lifecycle, capability
negotiation and renderer mailbox behavior. They do not substitute for on-device
Binder/GPU or full image qualification. Merge verification confirmed runtime,
integration and test sources matched the previously published feature branch;
existing `main` tooling additions were retained. `git diff --check` passed.

The tutorial review checked 77 relative links and eight shell-example syntax
blocks. Device/build measurements are the prior dated receipts linked below;
no new full AOSP build, flash, device regression, or update activation was
performed to cut this source release.

## Known limits and deployment boundary

- This is a **developer/reference source release**, not a production-certified
  device image or an APK/APEX that bootstraps untouched Android.
- The current platform relay requires custom HAL AIDL **V6**. APEX package
  version **8** in source is a separate version space from release **v0.1.0**;
  neither asserts that the device is running package 8.
- Pi/A17 validation uses a userdebug/test-signed, SELinux-permissive base.
  Earlier A13 Enforcing/staged-update evidence applies only to its matched
  cohorts. Pi staged updates, rebootless activation and production rollback/
  recovery are not qualified. The reference installer intentionally pins an
  older A13 base and must not have its guards bypassed.
- A diagnostic 1080p120 camera-only workload sustained 120 successful results/s;
  independent pixel decoding remained near 60 distinct frames/s. Full split
  1080p120 was GPU-limited (~12.9 results/s in the cited run). These are different
  workloads: **120-fps fresh-pixel delivery and optical latency are not qualified**.
- Clear-before-overwrite and extended-deadline experiments remain diagnostic,
  default-off settings; they are not silently promoted by this release.
- The Pi clock overlay has a recorded unresolved missing-glyph artifact. Matching
  clocks or callback counters are not precision display-latency measurements.
- General multi-camera, YUV/JPEG, 4K, long-soak, all-app and cross-BSP compatibility
  must be qualified on each intended target. Advertising modes is not proof of
  their sustainable throughput.
