# Source-level investigation map

These are examined code paths, not an assertion that every path is the bottleneck. Line numbers refer to the measured checkout; source revisions are recorded in capabilities-summary.json.

- **HAL work:** `hal/core/GpuCompositor.cpp::composite`: source EGLImage import, destination AHardwareBuffer clone/EGLImage import, renderbuffer creation, full-frame textured quad, native completion fence and per-frame teardown. Buffer lifetime/fence-aware image caching is a CPU-cost candidate, not a way to remove the full-frame GPU pass.
- **Producer work:** `targets/rpi5-a17/apps/VCamProducer/.../VCamProducerService.java`: per-pixel scene shader; `ClockTexture.update` redraws a512×256 bitmap using Canvas/String.format and uploads it every frame; `DirectMirror.draw` draws again into a second EGL window. The left TextureView then participates in app RenderThread rendering. A glyph atlas/GPU-native clock and genuine render-once reuse are separate candidates.
- **Allocation:** `external/minigbm/cros_gralloc/cros_gralloc_helpers.cc`: HW_COMPOSER requests scanout. Mesa wrapper calls legacy `gbm_bo_create` with scanout usage, not negotiated explicit modifiers. `external/mesa3d/src/gallium/drivers/v3d/v3d_resource.c:846` forces legacy scanout resources linear. The current display's advertised RGB layout support is not V3D UIF. Matched `v3d_screen.c:640–687` advertises UIF and LINEAR for RGBA, while runtime KMS AB24 planes advertise VC4_T_TILED and LINEAR. Their observed/source-advertised intersection is LINEAR; explicit negotiation alone would not conjure a shared tiled layout.
- **Tile work:** Mesa `v3dx_draw.c::v3d_update_job_tlb_load_store` constructs `no_load_mask = clear_tlb | clear_draw | invalidated_load`; otherwise marks destination color for tile load. `v3dx_rcl.c::v3d_rcl_emit_loads` emits those loads. This source path supports the clear-before-overwrite mechanism; without GPU byte counters we do not claim a measured memory-bandwidth ceiling.
- **GPU counters:** Mesa `v3d_query_perfcnt.c` uses per-context kernel PERFMON objects and job fences. A CPU simpleperf cache-miss counter is not a GPU bandwidth counter. Proper GPU counter collection needs a supported per-context performance-query path; ordinary ftrace provides job timing, not bytes transferred.
- **Relay/queue:** `platform-jni/VirtualCameraRelayJni.cpp` creates BufferItemConsumer with max-acquired2 and texture usage, forwards real acquire fences through Binder and retains the current item until a returned read fence permits release. `VirtualCameraStableHal.cpp` maintains the latest frame, sequence/configuration identity and in-flight readers. This is not an unbounded30-frame batch.
- **Camera requests:** `hal/aidl-v1/VirtualCameraSession.cpp` advertises maxBuffers4 for streaming. The source is required to be fresh. Availability plus readiness share one requested frame period after startup; cancellable2ms polling can add observation delay. Destination sync_wait can wait up to100ms. These bounds are not measured normal costs; profiles determine actual time spent.
- **HWC:** `external/drm_hwcomposer/drm/DrmFbImporter.cpp` distinguishes linear drmModeAddFB2 from modifier-aware drmModeAddFB2WithModifiers. `DrmPlane.cpp` handles optional IN_FENCE_FD; atomic state manager handles commit/fence lifetime. Unsupported scanout formats require validation/fallback, not masking usage bits.
- **KMS:** inspect active CRTC mode, plane IN_FORMATS, vblank events and present fences. No mode-setting commands are used. An advertised tiling modifier alone does not prove that V3D can render that layout efficiently, nor that a given scaled atomic composition will pass TEST_ONLY.
- **Scheduling/power:** private sched/V3D/DRM traces and boundary clock/temperature snapshots. No affinity, priority, governor or kernel changes are used to manufacture favorable results.
- **Diagnostics:** console suppression and screenrecord controls are isolated. Existing bootreceiver/drm/wifi trace instances remain untouched. Baseline screenshots are taken only outside timed windows.

## Candidate changes and their prerequisites

1. **Clear before full overwrite:** preserve fences and the full-coverage replacement contract; expand beyond monochrome marker samples before broad/default enablement. It avoids old destination tile loads; it does not eliminate the output pass.
2. **Left-pane SurfaceView:** remove remaining per-frame app TextureView composition, then measure the new source/output layouts and total GPU work. Preserve one-compositor Freeze behavior and lifecycle handling.
3. **Render once, reuse correctly:** design explicit shared-buffer ownership and fences. The prior offscreen prototype still rendered the mirror independently and was rejected; simply adding another offscreen texture can increase work.
4. **GPU-native clock/glyph atlas:** avoid per-frame Canvas/text formatting/bitmap upload. Compare with identical visible content; a blank/simple benchmark is not a product replacement.
5. **Event-driven source readiness:** replace bounded polling with a cancellation-aware notification/fence design. Maintain generation invalidation, stop/reconfigure responsiveness and release-fence safety. Do not achieve a higher result count by replaying stale frames or extending deadlines silently.
6. **Import/resource caching:** key by actual buffer identity plus configuration/lifetime, not reused integer IDs alone. Measure the observed import cost first; retain safe eviction and in-flight GPU references.
7. **Allocator/Mesa/KMS changes:** investigate only a real common supported format/layout or a measured conversion strategy. Current RGB intersection is linear; forcing UIF or clearing HW_COMPOSER usage is not a valid optimization.
8. **Kernel/governor changes:** conditional on measured runnable delay, frequency drops, IRQ stalls or thermal correlation. Do not prioritize blind affinity/priority tweaks over confirmed graphics work.

Each candidate should be tested independently, then combined only after correctness and whole-pipeline performance are measured. A successful callback rate alone is insufficient acceptance.
